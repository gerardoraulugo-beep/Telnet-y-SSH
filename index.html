1. Introducción

Acceso remoto en redes de computadoras

En las redes de computadoras es necesario administrar dispositivos como routers, switches y servidores. Una de las formas de hacerlo es mediante un acceso remoto. El acceso remoto permite que un administrador se conecte a un dispositivo desde otra computadora utilizando la red, sin tener que estar físicamente frente al equipo. Dos protocolos relacionados con esta tarea son Telnet y SSH.

Telnet

Es un protocolo utilizado para acceder remotamente a un dispositivo mediante una conexión TCP.

SSH

Secure Shell permite administrar dispositivos remotamente incorporando mecanismos criptográficos para proteger la comunicación.

2. ¿Qué es Telnet?

Telecommunication Network

Telnet es un protocolo de comunicación que permite establecer una sesión de terminal remota con otro dispositivo conectado a una red. Su especificación principal está definida en el RFC 854. Utiliza una conexión TCP para transportar los datos y la información de control. En términos sencillos, Telnet permite controlar un dispositivo de red desde otra computadora mediante comandos.

Puerto

TCP 23

Protocolo

TCP

Interfaz

Línea de comandos

Administración

Routers, switches y otros dispositivos.

3. Características de Telnet

Administración remota

Permite acceder a dispositivos desde otra computadora.

TCP

Utiliza el protocolo de transporte TCP.

Puerto 23

Utiliza normalmente el puerto TCP 23.

CLI

Permite trabajar mediante una interfaz de línea de comandos.

Equipos de red

Puede utilizarse para acceder a routers y switches.

Protocolo antiguo

Es un protocolo de acceso remoto tradicional.

Seguridad

No proporciona cifrado adecuado para proteger las credenciales y los datos de una sesión.

4. ¿Cómo funciona Telnet?

El usuario inicia la conexión

Desde una computadora se solicita una conexión hacia la dirección IP del dispositivo.

Se establece la conexión TCP

El cliente Telnet establece una conexión con el dispositivo utilizando TCP.

Autenticación

Dependiendo de la configuración, el dispositivo puede solicitar usuario y contraseña.

Inicio de sesión

Si las credenciales son correctas, el usuario obtiene acceso a la línea de comandos.

Ejecución de comandos

Por ejemplo: 

show running-config

Finalizar conexión

El usuario puede cerrar la sesión cuando termina de administrar el dispositivo.

5. Problemas de seguridad de Telnet

Sin cifrado seguro

Telnet no proporciona la protección criptográfica que proporciona SSH.

Información sensible

En una red insegura, un atacante que consiga observar el tráfico podría obtener información sensible.

Sniffing

El tráfico puede ser observado mediante herramientas de captura de paquetes en determinados escenarios.

Man-in-the-Middle

La falta de mecanismos de protección del protocolo puede permitir determinados escenarios de ataque.

6. ¿Qué es SSH?

Secure Shell

SSH significa Secure Shell. Es un protocolo diseñado para proporcionar acceso remoto seguro a sistemas y dispositivos a través de una red. El estándar RFC 4253 describe SSH como un protocolo para inicio de sesión remoto seguro y otros servicios de red sobre redes que pueden considerarse inseguras. Proporciona cifrado, autenticación del servidor e integridad de la información.

Puerto

TCP 22

Cifrado

Protege la comunicación mediante criptografía.

Autenticación

Permite autenticar al usuario.

Integridad

Protege la integridad de los datos.

7. Evolución de SSH

1995

SSH fue creado por Tatu Ylönen como una alternativa para proporcionar acceso remoto seguro.

SSH-1

Fue la primera versión, pero actualmente se considera obsoleta debido a problemas estructurales de seguridad.

SSH-2

Es la versión utilizada como estándar actual y cuenta con mejoras en el intercambio de claves y seguridad.

8. ¿Cómo funciona SSH?

Inicio de conexión

ssh usuario@192.168.1.1

Establecimiento de comunicación

El cliente SSH intenta establecer una conexión con el servidor SSH.

Intercambio criptográfico

SSH negocia mecanismos criptográficos para proteger posteriormente la comunicación.

Autenticación

El usuario proporciona sus credenciales. 


Username: administrador
Password: ********

Sesión segura

Una vez autenticado, el usuario puede ejecutar comandos remotamente.

Cierre

Cuando termina la administración, se cierra la conexión.

9. Criptografía utilizada en SSH

Protección de la comunicación

Cifrado simétrico

Se utiliza para la transferencia de datos una vez establecida la sesión. Ejemplos mencionados en el material:

AES
ChaCha20

Cifrado asimétrico

Se emplea durante el intercambio inicial de claves y determinados mecanismos de autenticación.

Clave pública

Puede almacenarse en el servidor y participar en mecanismos de autenticación.

Clave privada

Debe mantenerse confidencial en el cliente.

HMAC

Los mecanismos basados en HMAC ayudan a garantizar la integridad de los mensajes.

Diffie-Hellman

Puede utilizarse durante el intercambio de claves para establecer una clave de sesión compartida.

10. Conexión SSH paso a paso

Handshake TCP

El cliente se conecta al puerto 22 del servidor.

Verificación del host

El servidor envía información utilizada para identificarlo. El cliente puede verificar la huella digital registrada.

Intercambio de claves

Cliente y servidor pueden utilizar mecanismos como Diffie-Hellman para establecer una clave de sesión.

Autenticación

Puede utilizarse una contraseña o un mecanismo basado en claves públicas y privadas.

Apertura del canal

Se establece el canal protegido para ejecutar comandos, realizar túneles o transferir archivos.

13. Telnet y SSH en Cisco

Administración remota mediante líneas VTY

En Cisco, tanto Telnet como SSH pueden utilizarse para administrar remotamente un router o switch. El acceso remoto normalmente se configura mediante las líneas VTY, conocidas como Virtual Terminal Lines. 


line vty 0 4

Esta configuración entra a la configuración de las líneas VTY.

14. Configuración básica de Telnet en Cisco


enable

configure terminal

hostname R1

enable secret cisco

line vty 0 4

password telnet

login

transport input telnet

end

Después, desde una computadora correctamente configurada, se puede intentar: 

telnet 192.168.1.1

La dirección IP dependerá de la configuración del router.

15. Configuración básica de SSH en Cisco


enable

configure terminal

hostname R1

ip domain-name redlocal.com

username admin privilege 15 secret cisco123

crypto key generate rsa

line vty 0 4

login local

transport input ssh

end

16. Hostname y nombre de dominio

Dominio

Forma parte de los parámetros utilizados para preparar el dispositivo para SSH y generar las claves criptográficas.

17. Usuario y contraseña


username admin privilege 15 secret cisco123

username

admin

Nombre del usuario.

18. Líneas VTY


line vty 0 4

login local

transport input ssh

Las líneas VTY son líneas virtuales utilizadas para conexiones remotas. La instrucción: 

transport input ssh

indica que se permite SSH como método de acceso entrante en esas líneas.

19. ¿Qué es RSA?

RSA es un sistema criptográfico utilizado en determinados escenarios para generar claves que participan en mecanismos de seguridad. En una configuración tradicional de SSH en Cisco puede aparecer: 


crypto key generate rsa

El router genera las claves necesarias para preparar el servicio SSH.

20. Verificación de SSH


show ip ssh

Este comando permite revisar el estado de SSH en Cisco. 



show running-config

Permite revisar la configuración activa.

26. Desventajas de Telnet

Sin cifrado

Exposición

Las credenciales y datos no reciben la protección criptográfica de SSH.

Redes no confiables

No es adecuado para administración remota segura sobre redes que no son confiables.

Administración remota

31. Importancia de Telnet y SSH

Estos protocolos son importantes porque permiten comprender cómo se realiza la administración remota de dispositivos. En un laboratorio de redes, por ejemplo, un administrador puede configurar un router sin estar conectado físicamente al puerto de consola. SSH permite realizar esta administración utilizando mecanismos de protección criptográfica.

34. Resumen para exposición

Telnet es un protocolo que permite conectarse remotamente a un dispositivo mediante una conexión TCP. Utiliza normalmente el puerto 23 y permite administrar equipos mediante comandos, pero no proporciona cifrado seguro para la sesión.

SSH, que significa Secure Shell, también permite administrar dispositivos remotamente, pero utiliza mecanismos criptográficos para proteger la comunicación.

SSH utiliza normalmente el puerto 22 y proporciona cifrado, autenticación e integridad.

En Cisco, ambos pueden utilizarse mediante las líneas VTY, aunque SSH se utiliza para administración remota segura.

35. Conclusión

Telnet y SSH son protocolos utilizados para el acceso remoto a dispositivos y sistemas.

Telnet fue diseñado para proporcionar comunicación remota mediante terminales y utiliza TCP. Sin embargo, no ofrece las protecciones criptográficas necesarias para considerar segura una sesión sobre una red no confiable.

SSH fue desarrollado para proporcionar acceso remoto seguro. Su diseño incorpora mecanismos de cifrado, autenticación e integridad de los datos.

Por ello, en el aprendizaje de redes es importante conocer ambos protocolos: Telnet permite comprender el acceso remoto tradicional, mientras que SSH permite estudiar cómo se protege ese acceso mediante mecanismos criptográficos.
